# PMI MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现一个可运行的个人长期记忆基础设施 MVP：SQLite 真相源 + 可重建索引 + 记忆演化引擎 + MCP/CLI/Python 三种接入，并用自动化测试证明需求 §11 的 10 个验收场景。

**Architecture:** 一个 `pmi.api.Memory` facade 承载全部业务；真相源 `data/memory/pmi.db`（来源、记忆、版本、证据、实体、关系、proposal、审计、变更 outbox）+ 原文目录 `data/sources/`；派生索引 `data/index/search.db`（chunk、FTS5、向量），通过 outbox 懒惰追平。PMI 不调 LLM，理解由调用方 Agent 完成；写入经策略引擎决定立即生效或进入待确认。

**Tech Stack:** Python 3.12（uv 管理）、标准库 `sqlite3`/`tomllib`、`mcp==2.3.0`（`MCPServer`）、`pypdf==7.0.0`、`python-docx==1.2.0`、`pyyaml==6.0.3`（仅用于 Markdown frontmatter）；可选 extra `semantic`：`fastembed==0.9.1`；测试 `pytest`。

**Spec:** `docs/design/2026-11-10-pmi-design.md`（原始需求：`docs/requirements.md`）。实现者必须同时读设计文档；本计划只写设计文档没有定死、而实现必须统一的决定。

## Global Constraints

- 项目根目录 `~/personal-memory/`，独立 git 仓；`data/`、`.venv/`、`config/settings.toml` 不进 git。
- `requires-python = ">=3.12"`，`.python-version` 为 `3.12`；所有命令通过 `uv run --frozen --extra semantic …` 执行。
- 依赖版本锁死如上；**不加载任何 SQLite 扩展**。
- 代码、注释、标识符、日志、错误信息用英文；README 和设计文档用中文。
- 时间一律存 UTC `YYYY-MM-DDTHH:MM:SSZ`；只有日期的输入按 `T00:00:00Z`。
- `pmi.db` 中**不存绝对路径**；`sources.file_path` 相对 `data/`。
- 每个真相变更在**同一事务**里写 `changes`（索引 outbox）和 `audit_log`。
- 写事务用 `BEGIN IMMEDIATE`；连接 PRAGMA：`journal_mode=WAL`、`foreign_keys=ON`、`busy_timeout=5000`、`synchronous=NORMAL`。
- 对外返回值全部是可 JSON 序列化的 dict；错误统一为 `{"error": code, "message": str, "details": dict}`。
- MCP 永远不暴露 confirm / forget / review。
- 默认 embedding 模型 `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`；运行时只用本地已下载的模型（`local_files_only=True`），下载只通过显式命令 `pmi model download`。
- ID 格式：`<prefix>_<ULID>`（26 位 Crockford base32，48 位毫秒时间 + 80 位随机），前缀 `src` / `mem` / `ent` / `prp`。
- 枚举（必须与设计 §6 一致）：
  - source kind `document|note|conversation|agent_output`；trust `owner|agent|external`
  - memory kind `episodic|semantic|project|person|decision|procedure|preference`
  - memory status `active|superseded|disputed|archived|forgotten`；verification `user_confirmed|source_backed|inferred`
  - entity kind `project|person|org|topic|system|other`；entity role `subject|owner|participant|mentioned`
  - link type `supersedes|contradicts|supports|relates_to|part_of`（`link` op 不允许 `supersedes`，替代只能走 `supersede` op）

### Task 2: 文本工具 `textnorm.py`

**Files:** Create `src/pmi/textnorm.py`；Test `tests/test_textnorm.py`

**Interfaces:**
- Produces：
  - `normalize_text(raw: str) -> str`：NFC；`\r\n`/`\r` → `\n`；去掉除 `\n`、`\t` 外的控制字符；去行尾空白；3 个以上连续换行压成 2 个；首尾 strip
  - `find_quote(text: str, quote: str) -> tuple[int, int] | None`：忽略空白差异的子串匹配，返回在**原始 `text`** 中的 `[start, end)`
  - `content_key(s: str) -> str`：NFKC + casefold，去掉所有空白和 Unicode `P*`/`S*` 类字符后取 sha256 hex
  - `fts_tokens(s: str) -> str`：用空格连接的 token 串
  - `query_terms(s: str) -> list[str]`：`fts_tokens` 的 token 去停用词、按出现顺序去重
  - `estimate_tokens(s: str) -> int`：CJK 字符数 + ceil(其余非空白字符数 / 4)
  - `normalize_slot(s: str) -> str`；`slugify(name: str) -> str`
  - `STOPWORDS: frozenset[str]`

`find_quote` 的算法（签名决定不了，写在这里）：把 `text` 中每段连续空白压成单个空格，同时记录「压缩后下标 → 原始下标」的映射数组；`quote` 做同样压缩并 strip；在压缩文本里 `find`；命中后通过映射数组换算回原始下标（end 取最后一个匹配字符的原始下标 + 1）。

`fts_tokens` 规则：NFKC + lower；连续 CJK 字符（Han、平假名、片假名、Hangul）展开为相邻二元组，长度为 1 的 CJK 段保留单字；其余部分按 `[^\W_]+`（排除 CJK）切词；数字保留。

`STOPWORDS` 内容（钉死，测试依赖）：英文 `a an the of to in on for and or is are was were be been what why how when who which do does did we our you i it this that with about at by from`；中文二元组 `什么 为什 我们 你们 他们 一个 这个 那个 是否 怎么 如何 的是 了吗 是什`。

`normalize_slot`：strip → lower → 空白换成 `-` → 连续 `-` 合并；必须匹配 `^[\w\-./]{1,120}$`（Unicode `\w`，允许中文），否则 `ValidationError`。`slugify`：lower，空白换成 `-`，去掉 `\w` 和 `-` 之外的字符。

op 结构（Agent 可见的契约，MCP 文档也按这个写）：
- `{"op": "create", "memory": MemoryInput}`
- `{"op": "supersede", "old_ids": [str, ...], "memory": MemoryInput}`：新建一条记忆并替代 old_ids
- `{"op": "supersede", "old_ids": [str, ...], "memory_id": str}`：用已存在的记忆（active 或 disputed）替代 old_ids；disputed 的那条转为 active

流程：
1. **先校验全部 op**：结构、枚举、引用的 id 存在且未遗忘、evidence 可解析。任何一条出错 → 抛 `ValidationError`，`details={"errors": [{"index", "message"}]}`，不写任何数据。

3. create 按设计 §7.2 的 11 行表**从上到下**匹配。几点实现约定：
   - 第 3 行的 archived 同内容记忆放进 `candidates`。
   - 第 7、8、9 行生成的 proposal，ops 分别是 `[{"op":"supersede","old_ids":[active_id],"memory":input}]`（第 7 行，新记忆不入库）和 `[{"op":"supersede","old_ids":[active_id],"memory_id":disputed_id}]`（第 8、9 行）；第 8、9 行另加 `links(contradicts, from=disputed, to=active)`。
   - 第 4 行在 `policy_inferred_create == "deny"` 时 outcome 为 `rejected`。
   - 新记忆的 verification：owner 传了就用；否则有 evidence → `source_backed`，没有 → `inferred`。
4. supersede：先对 old_ids 做 policy 判定（targets = old 记忆），`review` → 整个 op 进 proposal。apply 时的顺序：先把每条 old 更新为 `status=superseded, superseded_by=<new_id>, valid_until=<new.valid_from 或 clock.now()>`，再插入新记忆（`memory_id=new_id`，`ids.new_id` 预先生成），然后加 `links(supersedes, new → old)`。
5. 本任务里 `candidates` 只填第 3 行的 archived 同内容记忆；全文近似候选由 Task 15 的 facade 补充。
