# MVP 实现记录（2026-11-10）

计划：`docs/superpowers/plans/2026-11-10-pmi-mvp.md`（19 个任务全部完成）。设计：`docs/design/2026-11-10-pmi-design.md`。
本文记录实现过程中**偏离或补充计划的决定**、终审修复，以及**有意推迟**的问题。每条都写明「如果判断错了，代价是什么」。

## 一、实现中的决定

| # | 决定 | 原因 | 判断错了的代价 |
|---|---|---|---|
| 1 | 实体 / 记忆原语不自己开事务，由 evolution / facade 统一包事务 | SQLite 不支持嵌套 BEGIN；一次 propose 要跨多个原语原子提交 | 单独调用原语时逐句自动提交 |
| 2 | 证据合并（重复主张追加引用）只记审计，不升记忆版本号 | 版本追踪的是记忆自身字段；证据行自带 added_by / added_at | 历史视图看不到「何时补充了证据」 |
| 3 | owner 的主张不走第 7–9 行（无日期 / 受保护），直接替代 | 策略规定 owner 一切直接生效 | 你自己一条无日期的笔记能直接替换有日期的结论 |
| 4 | propose 在**同一个写事务**内先校验再应用，约束冲突转成 ValidationError 且不写入 | 避免校验与应用之间的竞态 | 无 |
| 5 | update 可改 active / disputed / superseded（允许修正历史错字），不能改 archived | 归档的先 restore | Agent 不能直接批注已归档记忆 |
| 6 | confirm 只接受 active / superseded | 确认已归档主张没有意义 | 需先 restore |
| 7 | 遗忘来源时同时清空 origin_key、file_path、file_hash；遗忘记忆时清空有效期、置信度和版本理由 | 路径和理由文本本身可能敏感 | 同一路径以后重新导入会从 v1 开始新链 |
| 8 | 会议记忆加 `meeting` 标签；格式错误的 `[slot: …]` 标签被忽略而不是中断整份纪要 | 一个坏标签不该丢掉整场会议 | 那条 bullet 不会自动替代 |
| 9 | 索引列名 span_start / span_end；mem_rows 存原文（向量需要原文）；chunk 的 FTS 词带上来源标题 | `end` 是 SQL 关键字 | 无（索引可重建） |
| 10 | 单个汉字的检索词不进 FTS（索引是二元组），只有没有多字词时才用 LIKE 兜底；as_of 视图排除 disputed | 有争议的主张从未在任何时刻生效 | as_of 视图看不到争议主张 |
| 11 | 全文命中规则：覆盖 1/3 查询，**或**命中 2 个不同的有效词（计划只写了覆盖率） | 中文自然问句会产生大量跨词二元组（在什 / 么时），让 Test 3 的问题找不到自己的决策 | 见终审 I2 的后续收紧 |
| 12 | 上下文召回包括 superseded，用来填充 history；as_of 模式只按有效期划分，不返回历史和冲突 | — | as_of 回答不带历史 |
| 13 | facade 的 owner 专用方法都接受可选 `actor=`，便于测试拒绝路径、MCP 共用一个实例；加别名会触发相关记忆重新索引 | 别名是记忆索引文本的一部分 | 无 |
| 14 | 「库里不存绝对路径」落实为：file_path 永远相对 data/，PMI 自身路径不出现在库里；主目录外文件的 origin_key 仍是 `file:/<绝对路径>`（设计 §6.1 原文） | 设计两处都写了，以更具体的那条为准 | 被导入的**原文件**移动后接不上版本链 |
| 15 | 导出格式为 `{"type": 记录类型, "row": {...}}` | 平铺会和 links.type 列冲突（测试发现） | 无 |
| 16 | backup / export / 模型下载仅 owner；verify / doctor 所有人可用 | MCP 不暴露这些 | 无 |
| 17 | `--home` / `--json` 在子命令前后都可写；只有检索、导入、提议类命令才加载模型 | 其他命令启动更快 | 无 |
| 18 | MCP 工具调用用锁串行（每个服务进程一个 SQLite 连接） | SDK 可能在工作线程跑同步工具 | 同一客户端的并发调用会排队 |
| 19 | 迁移前备份用 SQLite 在线备份 API，不用文件复制 | 文件复制可能漏掉 WAL 里的内容 | 无 |
| 20 | 验收 test_01 / test_10 改为 Agent 直接传文本，不传 examples/ 路径 | Slack Agent 本来就传文本；examples/ 不在默认可读目录内 | 无 |
| 21 | 提取出的 op 的 valid_from 用规范化后的时间戳 | 来自来源的 source_time | 无 |
| 22 | content_key 规则修改后，旧数据的 key 不回填 | 当时还没有真实数据 | 如有旧库，少数带数字标点的记忆在被重新保存前不会与新主张去重 |
| 23 | 只靠弱向量命中（相似度 < 0.65）回答的跨语言问题，现在报 insufficient_evidence=true，但仍列出该记忆 | 「宁可说不知道，也不编造」 | Agent 在跨语言问题上可能说得过于保守 |

**并发测试发现并修复的 3 个真实竞态**：两个进程同时初始化新库导致重复迁移；WAL 模式切换不受 busy_timeout 保护；索引文件在别的进程建表过程中被误删。

## 二、终审修复（独立 reviewer，Opus）

| 级别 | 问题 | 修复 |
|---|---|---|
| 严重 C1 | Agent 只要再附一句目标文档里的引用，就能绕过「低可信度证据不能改 owner 文档支撑的记忆」 | 授权可信度改为：新证据中、不属于目标现有来源的那些来源里**最低**的可信度；引用至少 4 个非空白字符（设计 §7.3 已修订） |
| 重要 I1 | Agent 可以用相同 origin_key 接管你文档的版本链 | 链上最新版本可信度更高时，拒绝低可信度来源追加新版本 |
| 重要 I2 | 已知项目问未知问题时 insufficient_evidence 恒为 false；未知项目会借用别的项目的事实；真实模型下实体名让无关文本相似度达 0.5–0.6 | 常见词不算命中；问题中的实体算一次命中；只靠实体召回不算证据；向量召回去掉实体名；只有 ≥ 0.65 的纯向量命中才算证据 |
| 重要 I3 | 遗忘后原文仍可从数据库字节、WAL 和之后的备份中恢复 | secure_delete；遗忘后 FTS optimize + WAL checkpoint(TRUNCATE)；`verify --fix` 清理孤儿文件 |
| 重要 I4 | 中文日期让提取整体失败；超过 50 条无法提取；提取失败后无法重试 | 支持「2026年10月1日」等格式；分批提交；失败只报告不抛错；重复导入时若未提取过会重试 |
| 重要 I5 | 一个读不了的文件或 pypdf 异常会中断整批导入 | 每个文件单独捕获所有异常 |
| 重要 I6 | 索引等锁超时或 embedding 出错会删除并重建正被其他进程使用的索引；写入后的同步错误被报成写入失败 | 忙 / 锁 → 跳过并提示；只有损坏才重建；写入后的问题只作提示 |
| 重要 I7 | 「预算 35 万」被当成「预算 3.5 万」的重复；不同项目 / slot 的同文本被合并 | 保留数字内标点；重复必须同 kind、同 slot、同实体 |
| 重要 I8 | 乱序补录历史时历史链没有重排，as_of 返回两条 | 插入到真实的前后邻居之间 |
| 重要 I9 | 只设了 owner 密码、可直接打开的 PDF 被拒 | 先尝试空密码 |
| 升级 | 审批列表只显示 id，你会在没看到内容的情况下「确认」 | 预览显示将被替代 / 激活记忆的全文、引用和可信度 |
| 升级 | Agent 可让 PMI 读取整个主目录（含 ~/.ssh） | 默认只允许 ~/Documents、~/Desktop、~/Downloads；拒绝隐藏文件和目录 |
| 升级 | Agent 不带证据的 supersede 绕过审批 | 按「无证据推断」处理，默认进审批 |

## 三、有意推迟的问题（Minor）

1. 只遗忘最新版本（`--this-version`）时，文档会从检索中消失，不会把上一版恢复为最新。
2. COMMIT 本身失败时 write_tx 不回滚（长驻 MCP 进程可能卡住；目前没有已知触发条件）。
3. chunk id 会复用，并发重切分时可能把旧向量挂到新 chunk 上（索引可重建）。
4. 你自己的笔记若与已有 agent / external 来源文本完全相同，会去重到那条低可信度来源上。
5. Agent 触发的提取在审计里记为 `extractor`，而不是 `agent:<客户端>`。
6. 同一批 op 按批前状态校验（如 [归档 X, 更新 X] 会更新到已归档记忆）。
7. 提案失败后遗留的 disputed 记忆只能由你用归档 / 替代处理；confirm 的报错仍指向那个已失败的提案。
8. 中文 @提及会吞掉后面的字（「@张三负责…」→ 人名「张三负责…」）；约定：名字后加空格。
9. 意图词按子串匹配（"now" 会命中 "know"）。
10. kind / 实体 / 时间过滤在 FTS 前 200 条之后才执行，数据量很大时可能漏结果。
11. `restore --force` 会把 data/models 一起移到 data.bak-*，需要重新下载模型；恢复前请先停掉 Agent。
12. 「database is locked」对 MCP 显示为 internal/OperationalError；CLI 遇到意外异常时打印堆栈而不是 JSON。

## 四、reviewer 提出但判定维持现状的点

| 点 | 维持的理由 | 代价 |
|---|---|---|
| 无 slot 的 Agent 主张与有 slot 的 owner 主张并存时不报冲突 | 设计 §14 接受；有可信度标注 | 「最新」类问题里 Slack 主张可能排在前面 |
| 没有操作系统级隔离 | 设计 §12 声明的单用户边界 | 本地进程可绕过策略 |
| 英文全文检索不做词形还原 | 计划约定按原词；语义检索补足 | 无模型时 "launches" 搜不到 "launch" |
| 向量暴力检索 | 个人量级（< 约 20 万 chunk）可接受 | 数据量很大时变慢 |
| 超大来源的引用匹配在写锁内进行 | 实测 500 万字约 0.22 秒 / 条 | 短暂写入争用 |
| Agent 是否听从注入文本 | 在 PMI 之外；PMI 只做标注、从不按内容行动 | 取决于 Agent |
| 对外部文本开启 extract 时会自动选 slot / 日期 | 仍受策略和可信度保护约束；Agent 本来也能直接写同样的 op | 外部的类纪要文本会生成未确认记忆 |
| Agent 可无限制地创建待审批提案 | 单用户可直接拒绝或忽略 | 审批队列可能嘈杂 |
| 非 macOS 平台 | 设计 §3 声明不在范围内 | 在 Linux / Windows 上的行为未知 |
